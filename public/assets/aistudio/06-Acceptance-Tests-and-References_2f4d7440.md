# Acceptance tests and engineering references

## Test fixture

Use disposable projects and identities. Project A uses Asia/Makassar with a shift at 08:00. Project B uses another timezone and different memberships. Include Owner, Contractor, Architect, Accounting, two Foremen with separate assigned teams, a Worker, a restricted viewer and an anonymous visitor. Build a register of at least 60 sheets with multi-page PDFs, duplicate titles, distinct revisions, source notes, two floors, a verified side elevation and one combined Electrical + Plumbing sheet. Use synthetic assets with a visible demo label for demos. Seed four departments, then add one. Include a month with no allocation, posted material issues, a reversal, an open commitment, and one incomplete source price.

Execute tests per stage. Record ID, build, environment, actor, input, observed outcome, and evidence. Use Pass / Fail / Unverified. A source-code inspection or a screenshot of a disabled control is not an end-to-end pass.

## Research and code models

Use these as reference implementations. Record the exact version and license only when adding a dependency. VONTA already has a renderer, routing and project UI. Source repositories and maintainer histories provide attributable engineering examples; public metadata cannot certify how every modern line was authored.

| Topic | Application in VONTA | Reference |
| --- | --- | --- |
| Sheet register | Stable sheet number, discipline, revisions and collections for field teams. Use these to find an issued sheet in a large set. | [Autodesk Build Sheets list](https://help.autodesk.com/cloudhelp/ENU/Build-Sheets/files/Work_With_Sheets_list_Autodesk_Build.html) |
| PDF preview | Load pages individually. Preserve original scale and file. Use small thumbnails and a high-resolution active canvas. | [Mozilla PDF.js examples with full source](https://mozilla.github.io/pdf.js/examples/) |
| Lightbox | Previous/next, captions, zoom and managed modal focus. Dmitry Semenov’s PhotoSwipe repository links the earlier v4 implementation for provenance. | [PhotoSwipe repository and history](https://github.com/dimsemenov/PhotoSwipe) · [WAI dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| Scrollspy and hover rail | Observe the real scroll container. Keep revealed content reachable while pointer or focus is inside. | [Bootstrap Scrollspy](https://getbootstrap.com/docs/5.3/components/scrollspy/) · [W3C hover/focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) |
| Chart sizing | Size the container before rendering. Recompute on actual container resize and preserve plot height across data filters. | [Apache ECharts, chart size](https://echarts.apache.org/handbook/en/concepts/chart-size/) · [Apache source code](https://github.com/apache/echarts) |
| Board views | Present one dataset in multiple layouts. Keep domain permissions separate from visual grouping. | [GitHub Projects board](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/customizing-the-board-layout) · [SortableJS source](https://github.com/SortableJS/Sortable) |
| Surface drawings and color | Use actual intersections with eligible meshes and plane-local geometry. Reuse an established wheel design and expose a fallback for eyedropper support. | [Three.js Raycaster](https://threejs.org/docs/pages/Raycaster.html) · [Three.js dashed lines](https://threejs.org/docs/pages/LineDashedMaterial.html) · [iro.js source](https://github.com/jaames/iro.js) · [MDN EyeDropper](https://developer.mozilla.org/en-US/docs/Web/API/EyeDropper_API) |
| Password and camera | A signed-in account can obtain a reauthentication challenge. Ensure every password change completes the registered-email proof. Request camera access through the browser permission flow. | [Supabase reauthentication](https://supabase.com/docs/reference/javascript/auth-reauthenticate) · [Update user](https://supabase.com/docs/reference/javascript/auth-updateuser) · [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) |
| Sharing | Separate audience from permission. Apply Viewer in both modes and explicit membership to edit. | [Google Drive sharing model](https://support.google.com/drive/answer/2494822) |
| Prompt design | Delimit role, context, source facts, actions and acceptance conditions. Execute in stages against observable tests. | [Google Gemini prompting guide](https://ai.google.dev/gemini-api/docs/prompting-strategies) |

The user’s prompt-engineering modules informed the ten-block prompt. The visual reference kit informed the edit boundary and regression review. Preserve the original brand, use real data and geometry for functional screens, and compare altered regions against the screenshots. Use the gallery reference for layout only.
